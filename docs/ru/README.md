## 🎯 О проекте

**Finance Manager** - кросс-платформенное приложение для личного учета финансов. Написано на .NET 9 с использованием MAUI Hybrid и Blazor Server: одна кодовая база работает нативно на Windows, Android и в Web-версии.

Большинство финансовых приложений на российском рынке не выходят за пределы базового ввода расходов. Никто не объединяет импорт банковских PDF-выписок, перехват уведомлений, поддержку криптовалюты и нативное приложение для Windows в одном продукте. Finance Manager закрывает этот пробел.

> 361 файл · 15+ модульных библиотек · 3 платформы · 1 разработчик

## ⚡ Функциональность

![Обзор платформ Finance Manager — счета, транзакции, цели](../../assets/screenshots/1.jpg)

### 🏦 Управление счетами

Полный CRUD для счетов всех типов: банковские карты, наличные, криптовалютные кошельки, вклады, электронные кошельки, инвестиции, кредитные карты. Мультивалютность - ₽, $, € и 15+ криптовалют с конвертацией в реальном времени. Группировка по типам счетов с раздельной статистикой. Пагинация карточек.

### 💸 Транзакции

**Ручной ввод.** пакетное добавление до 10 транзакций за раз, все типы: доход, расход, перевод между счетами.

**Автопарсинг PDF.** собственный модуль `DataIngestion` распознает транзакции из выписок и предлагает сохранить на выбранный счет. На данный момент уже имеет поддержку 6 популярных банков. Архитектура модуля позволяет добавить новый банк без изменения основной логики.

**Перехват уведомлений.** на Android приложение перехватывает системные уведомления и SMS банков, разбирает их и автоматически создает транзакции. Список отслеживаемых банковских приложений настраивается пользователем.

**QR-сканер.** сканирует QR-коды с чеков, получает данные через ФНС API.

Поиск по описанию, заметке и тегу; фильтры по типу/периоду/категории; группировка; массовые операции; экспорт CSV и PDF; мини-график активности по неделям.

Быстрые суммы. Статусы: Активна / На паузе / Завершена / Архив. Окно подтверждения при удалении. Настраиваемый стиль отображения суммы.

### ⚙️ Настройки

**Внешний вид.** светлая/темная/системная тема, 6 изменяемых акцентных цветов. Изменения применяются мгновенно через JS Interop в CSS Custom Properties - без перезагрузки страницы.

**Финансы.** основная валюта, месячный бюджет с порогом предупреждения, день начала финансового месяца, скрытие балансов, учет кредитных счетов в общей сумме.

**Уведомления.** гранулярное управление: новые транзакции, крупные расходы, превышение бюджета, недельный отчет, завершение импорта.

**Безопасность.** смена пароля, отображения списка активности использования приложения, настройка двухфакторной аутентификации в профиле.

Настройки сохраняются в PostgreSQL и все не чувствительные поля кешируются в SQLite. Применяются при каждом запуске приложения, работают офлайн.

### 🔐 Авторизация

Регистрация с оценкой сложности пароля, вход через Cookie+JWT, полноценный TOTP с QR-кодом и резервными кодами.

## 🎨 Дизайн

Интерфейс был разработан совместно с дизайнером. Каждая страница проходила несколько этапов проверок, прежде чем попасть в production.

**Адаптивность.** компоновка страниц корректно перестраивается в зависимости от размеров окна - элементы масштабируются и перегруппировываются от мобильного экрана до широкого монитора без потери читаемости, удобства и функциональности.

**Удобство.** ключевой принцип. Например, в разделе целей можно прямо в модальном окне пополнения создать новый счет, заполнить его и автоматически привязать к цели - без лишних переходов по меню.

**Внимание к деталям.** тонкая цветная полоска сверху карточек, плавные эффекты при наведении, простой скелет страницы при загрузке, всплывающие уведомления, анимация индикаторов. Каждое действие сопровождается визуальной обратной связью.

**Цветовая система.** терракот `#9E4F15` как основной акцент и дополнительные цвета, в сумме, лаконично образуют единую палитру. Для темной темы подобраны контрастные цвета относительно светлой палитры с сохранением стиля приложения. Вся цветовая палитра была выбрана для удобного длительного использования приложения.

**Компонентная база.** новые страницы строятся из общих готовых компонентов, настроенных стилей для разных элементов, что исключает дублирование и расхождения элементов между платформами или страницами.

## 🏗 Архитектура

### Ключевые архитектурные решения

**Двойная БД стратегия.** PostgreSQL хранит все пользовательские данные. SQLite на устройстве кеширует все не чувствительные данные - приложение работает офлайн, применяя последние известные настройки.

**`DataIngestion` - изолированный парсер данных.** отдельная библиотека, построенная на паттернах **State + Decorator**. Принимает любые "сырые" строки (PDF или текст SMS/Push), возвращает типизированный `ParseResult`. Каждый этап конвейера - нормализация, парсинг, маппинг и т.д. - заменяются независимо через интерфейсы, что благоприятно сказывается на расширяемости, масштабируемости и простоты тестирования отдельных блоков библиотеки. 
Для покрытия большего количества банков была разработана дополнительная система **Lua-скриптовое API**, для создания и подключения пользовательских парсеров с возможностью их миграции в глобальную систему.
Каждый парсер привязан к системе версий с датой своего создания. При изменении шаблона банком новая версия добавляется рядом со старой. Старая остается активной для обработки менее актуальных выписок. Версии отключаются полуавтоматически, когда формат парсера окончательно устарел.

```csharp
// Единственный публичный контракт модуля DataIngestion
public class ParseResult {

    public bool Success          { get; init; }
    public string? ErrorMessage  { get; init; }
    public List<ParsedTransactionDto> Transactions { get; init; } = [];

    public static ParseResult Ok(List<ParsedTransactionDto> transactions)
        => new() { Success = true, Transactions = transactions };

    public static ParseResult Fail(string error)
        => new() { Success = false, ErrorMessage = error };
}

// Данные попадают в систему модуля и возвращают готовый результут
string rawData = rawService.GetRawString();
ParseResult result = bankStatement.ParseBankStatement(rawData);

if (!result.Success) {
    Logger.LogWarning("Парсинг не удался: {Error}", result.ErrorMessage);
    return;
}

await SaveTransactionsAsync(result.Transactions);
ShowToast($"Импортировано {result.Transactions.Count} операций");
```

**`FinanceManager.Secure` - библиотека криптографических операций.** все алгоритмы скрыты за единым фасадом. Замена реализации не затрагивает вызывающий код - только внутренности библиотеки.

**Произвольная точность вычислений.** все финансовые суммы хранятся в EDecimal через `PeterO.Numbers`. Благодаря этому не возникает ошибок IEEE 754. Криптовалюта отображается с точностью, которую вернул API, и не обрезается, и не округляется принудительно.

**Кеширование настроек.** `UserSettingsService` загружает настройки при входе и сохраняет обновления в SQLite и периодически обновляет PostgreSQL. При отсутствии соединения настройки читаются из локальный кешируемых данных. Тема и акцентный цвет применяются через CSS Custom Properties при старте приложения.

```csharp
// AmountFormatter - единый статический сервис форматирования числовых значений
// Фиат: N0 для целых, N2 для дробных
AmountFormatter.Format(EDecimal.FromString("1234567"))   // "1 234 567"
AmountFormatter.Format(EDecimal.FromString("1234.56"))   // "1 234.56"

// Криптовалюта: Точность ограничена самой валютой, переданной от внешнего API
AmountFormatter.Format(amount, CryptoCurrencyCode.BTC)   // "0.00123456"
AmountFormatter.Format(amount, CryptoCurrencyCode.USDT)  // "120.00"

// Автоопределение по типу счета
AmountFormatter.Format(acc.Balance, accountDto)
AmountFormatter.GetSymbol(accountDto)                    // "₽", "$", "BTC", "ETH" и т.д.
```

## 🔐 Безопасность

### Слои защиты

**Хранение паролей.** Многопроходное хеширование с параметрами, настроенными под production-нагрузку. Хранимый хеш не позволяет восстановить исходный пароль даже при компрометации базы данных.

**Шифрование данных.** Чувстввительные данные защищены шифрованием и криптографической подписью.

**Аутентификация сессий.** Два независимых механизма под разные клиенты:
- Для браузера: Cookie устанавливаются сервером, недоступны из клиентского JavaScript, атрибуты выставлены по современным рекомендациям
- Для нативных MAUI-клиентов: JWT хранится в защищенном хранилище устройства, при каждом обновлении сессии токен заменяется на новый

**2FA (TOTP).** Настройка через QR-код или ручной ввод ключа, совместима с любым TOTP-аутентификатором. При активации выдаются резервные коды - единственный, на данный момент, способ восстановить доступ без устройства.

**Оценка пароля при регистрации.**

```csharp
// Оценка по энтропии, словарным атакам и пространству поиска
// Дополнительно созданы проверки для более точной оценки качества пароля пользователя
var result = Zxcvbn.Core.EvaluatePassword(password);

// Score: 0 - критически слабый, 4 - надежный
if (result.Score < 2)
    return ValidationError("Пароль недостаточно надежен");
```

### Клиентская часть

Клиент не получает и не хранит никакой чувствительной логики - она остается только на сервере.

### Серверная часть

Реализован комплекс мер против типичных векторов атак. Детали намеренно не публикуются.

## 🌐 Внешние API

### ЦБ РФ
Официальные ежедневные курсы валют: ₽/$/€.

### CoinGecko API v3
Курсы 15+ криптовалют в USD: BTC, ETH, USDT, USDC, BNB, SOL, XRP, ADA, AVAX, DOT, LINK, TRX, LTC, ETC, ATOM, MATIC, XLM, XMR.

### ФНС (Федеральная Налоговая Служба РФ)
Получение данных чека по QR-коду. Автоматическое создание транзакции.

> Запросы к внешним API ограничены, все полученный данные кешируются на необходимый срок, а затем переопределяются по мере его истечения.
